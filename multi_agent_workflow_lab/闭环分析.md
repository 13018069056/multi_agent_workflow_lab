# 失败反馈、修正、测试通过闭环分析

## 一、闭环执行结果

运行 python main.py 后，工作流成功执行并输出：

status: done
attempts: 2
tests_passed: True
human_approved: True

完整的状态转移历史如下：

| Step | 节点 | 状态 | 消息 |
|------|------|------|------|
| 1 | start | created | 实现一个 add(a, b) 函数，返回两个数字之和 |
| 2 | planner | planning | 形成四步执行计划 |
| 3 | programmer | coding | 生成第 1 版代码 |
| 4 | reviewer | reviewing | 当前代码使用了减法，不符合 add 函数需求 |
| 5 | router | reviewing | 审查未通过，返回 Programmer |
| 6 | programmer | coding | 生成第 2 版代码 |
| 7 | reviewer | reviewing | 代码逻辑符合加法需求 |
| 8 | tester | testing | 测试通过 |
| 9 | checkpoint | done | 检查点自动批准，工作流结束 |

## 二、闭环三阶段分析

### 第一阶段：失败反馈（Step 1-5）

工作流启动后，Planner 将目标拆解为可执行的4步计划。Programmer 生成第一版代码：

def add(a, b):
    return a - b

Reviewer 审查代码，检测到使用减法而非加法，给出明确的失败反馈：

当前代码使用了减法，不符合 add 函数需求

Router 根据 review_passed=False 决定返回 Programmer 重新生成。

### 第二阶段：修正（Step 6-7）

Programmer 接收到 Reviewer 的反馈后，生成第二版代码：

def add(a, b):
    return a + b

Reviewer 重新审查，设置 review_passed=True，审查通过。

### 第三阶段：测试通过（Step 8-9）

Tester 执行代码，调用 add(2, 3) 验证：

- 实际执行结果：5
- 成功标准：add(2, 3) == 5
- 验证结果：tests_passed=True

Checkpoint 批准工作流完成，状态变为 done。

## 三、闭环关键指标变化

| 指标 | 初始值 | 最终值 | 说明 |
|------|--------|--------|------|
| attempts | 0 | 2 | 经过1次重试后成功 |
| review_passed | False | True | 审查从不通过变为通过 |
| tests_passed | False | True | 测试从不通过变为通过 |
| status | created | done | 工作流成功完成 |

## 四、核心结论

本次实验成功验证了多 Agent 协作的核心能力：

1. 失败检测：Reviewer 准确识别代码逻辑错误，提供明确的失败反馈

2. 自动修正：Programmer 根据反馈自我修正

3. 双重验证：Reviewer 审查 + Tester 测试

4. 闭环完成：经过1次重试，工作流成功完成

5. 可观测性：完整记录9步状态转移
